# v1.0.8.1 — Релиз

Текущая версия: **1.0.8.1** (version.json)

---

## ✅ Изменения

### 1. Защита от смешанного кэша после релиза
- **Проблема**: после заливки новой версии `index.html` обновлялся сразу, а `app.js`/`styles.css` браузер ещё ~10 минут отдавал из HTTP-кэша (GitHub Pages) — получалась смесь: новые элементы без стилей и без обработчиков (кнопка зума «1×» справа на чёрной полосе, тап без реакции, распознавание ШК из галереи не срабатывало)
- **Решение**: версионирование ресурсов — `styles.css?v=1.0.8.1`, `data.js?v=…`, `app.js?v=…`; при каждом релизе поднимать `?v=` вместе с версией
- Service Worker: сопоставление кэша без учёта query (`ignoreSearch: true`) — офлайн работает и с версионированными URL; кэш `foto-reports-v25`

### 2. Ошибки распознавания ШК больше не молчат
- Если распознавание фото из галереи упало с ошибкой — тост «Ошибка распознавания ШК» вместо тишины

### 3. Съёмка в сканере тоже распознаёт ШК автоматически
- Раньше фото без выбранного кода не распознавалось вовсе (`tryDecodeFromCapture` — устаревший одиночный decode). Теперь: фото в сканере без выбранного кода → `queueKESNDetection` — все ШК на кадре: 1 → сразу в отчёт + тост; 2+ → модалка выбора с рамками; 0 → окно ручного ввода (как у фото из галереи)
- `tryDecodeFromCapture` удалён
- Сценарий с выбранным кодом (рамка → подтвердить → фото) не изменился

### 4. «Выбор папки» — надёжность
- Ошибка выбора папки теперь показывает причину: «Ошибка выбора папки: NotAllowedError…»; для ошибок доступа — подсказка «Разрешите браузеру доступ к файлам (настройки Android)»
- Восстановление дескриптора: `queryPermission`; если «prompt» — тихий запрос разрешения на первом касании экрана; если «denied» — статус «⚠️ Доступ к папке запрещён» в настройках
- Автосохранение копий: при утере доступа — один тост «Доступ к папке утерян — выберите её заново в настройках» (без спама)
- Браузеры без `showDirectoryPicker` (iOS, старые Android): кнопка скрыта, подпись «Выбор папки недоступен в этом браузере»
- Напоминание: эта папка — защита от потери отчётов при очистке данных сайта (JSON-копии отчётов с фото в реальной папке на телефоне)

### 5. «Сохранить» в секции сохраняет всегда
- Раньше при неполных фото секция НЕ сохранялась (только тост «Не сделаны: …»). Теперь отчёт сохраняется и происходит переход к чек-листу всегда; тост: полная секция — «Секция сохранена», неполная — «Сохранено. Не сделаны: …» (до 3 имён, дальше «и ещё N»)

### 6. Завершение отчёта с неполными фото
- Системный `confirm()` заменён на модалку приложения (надёжно на iOS в установленном PWA, понятные кнопки): «Не все фото сделаны. Сделано X из Y. Завершить отчёт без всех фото?» → «Продолжить заполнение» / «Завершить»
- При полных фото завершение сразу, без модалки
- Новая кнопка **«Вернуться к отчёту»** на странице «Отчёт готов!» — возврат к чек-листу (статус отчёта снова «draft»)
- Сборка архива: при падении показывается тост с текстом ошибки (раньше catch молчал — причину жаловоб не видно)

### 7. Справка обновлена
- Сканер: зум 1×/2×/3×, фонарик, новое поведение «фото без выбранного кода» (все ШК на снимке), распознавание ШК из галереи
- Новый раздел «Сохранение и черновики»: кнопка «Сохранить», черновики, папка с копиями (защита от очистки данных сайта, недоступна на iPhone)
- «Чек-лист и завершение»: предупреждение при неполных фото, «Вернуться к отчёту»
- Уточнено: режим iOS (720p / ZXing) по умолчанию на iPhone

## 🧪 Чек-лист проверки (после заливки)

1. Открыть приложение **дважды** (первый запуск подхватит обновление, второй — уже чистая v1.0.8.1)
2. В настройках — «Версия приложения: 1.0.8.1»
3. Сканер КЕ/СН: кнопка **1× слева сверху** кадра, стилизованная; тап → 2× → 3× → 1×
4. Фото этикетки из галереи (долгий тап по ячейке КЕ/СН) → распознавание: код в отчёт / модалка выбора / окно ручного ввода
5. Сканер: НИЧЕГО не выбирать → «Сделать фото» этикетки → код должен добавиться сам (или модалка выбора / ручной ввод)
6. Секция с неполными фото → «Сохранить» → тост «Сохранено. Не сделаны: …» + переход к чек-листу; отчёт в черновиках сохранён
7. «Завершить отчёт» с неполными фото → модалка приложения (не системный диалог); «Продолжить заполнение» / «Завершить» работают
8. На странице «Отчёт готов!» → «Вернуться к отчёту» → чек-лист; в черновиках отчёт снова активный
9. iOS: настройки — кнопки «Выбрать папку» нет, подпись «Выбор папки недоступен в этом браузере»
10. Android/Chrome: ошибка выбора папки показывает её причину
