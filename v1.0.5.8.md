# v1.0.5.8 — Релиз

Текущая версия: **1.0.5.8** (version.json)

## ✅ ВСЁ СДЕЛАНО (сессия 24.07.2026)

### 1. ZXing-сканер на iOS — стабильный запуск
- Добавлен `waitReady` — ожидание `video.readyState >= 2 && video.videoWidth > 0` перед запуском ZXing
- Проверка на закрытие модалки (`modal.classList.contains('hidden')`) — отмена ожидания
- Решена проблема: сканер не стартовал с первого раза на iOS (чёрный кадр)

### 2. iOS — настройка сканера по умолчанию
- `getScannerRes()` и `loadSettings()` — на iOS при отсутствии сохранённой настройки выбирается `'ios'`
- На других устройствах по-прежнему `'medium'`

### 3. Обновление — проверка интернета через fetch вместо navigator.onLine
- `performUpdate()`: убрана ненадёжная `navigator.onLine` (VPN-баг — соединение есть, интернета нет)
- Реальная проверка: fetch `version.json` — если упал, тост «Обновление недоступно без интернета»
- Если есть ожидающий SW-апдейт (`_swReg.waiting`) — применяется сразу без проверки

### 4. КЕ — 2 фото вместо 1
- data.js: KE-типы получают `multi: true, maxPhotos: 2`
- app.js: KE/SN handler открывает галерею при достижении лимита (вместо preview)
- app.js: кнопка «Сделать фото» в галерее КЕ открывает сканер
- app.js: `keCamCapture` проставляет `photoNumber`, `renderKECell` показывает счётчик `1/2`
- app.js: сканер поверх галереи — после закрытия галерея обновляется

### 5. Хранилище отчётов — защита от сброса кэша
Два уровня:

**Уровень 1 — localStorage (всегда включён)**
- `saveReport()` дополнительно пишет stripped-копию (без фото) в localStorage
- `loadDrafts()` при пустом IndexedDB загружает из localStorage
- `deleteReport()` / `deleteCurrentReport()` чистят localStorage
- Ключи: `_rback_{id}` + `_rback_index`
- Переживает сброс кэша браузера

**Уровень 2 — File System Access (опционально, в Настройках)**
- Кнопка «Выбрать папку для сохранения копий с фото» в настройках
- `window.showDirectoryPicker()` → `FileSystemDirectoryHandle` сохраняется в IndexedDB
- При каждом сохранении отчёта — пишет полный `.json` (с фото) в выбранную папку
- При загрузке приложения — читает `.json` из папки (восстановление после сброса)
- Поддерживается в Chrome/Edge/Opera (не iOS Safari)

### 6. Версия v1.0.5.8
- `version.json: 1.0.5.8`, `sw.js: foto-reports-v20`

### 7. Фото ключей — только в Аптеке (сессия 30.07.2026)
- `klyuchi` удалён из кассовой зоны для ММ, МК, ГМ — остался только в Аптеке (MA)
- Подсказка изменена на: «Ключи РМК должны быть установлены в задние USB ПК.»

### 8. ZIP-архив — ускорение на Android 16
- Фото добавляются в zip через `fetch` + `Blob` вместо base64-строк (нативный парсинг браузера)
- Конвертация dataURL → Blob выполняется параллельно (`Promise.all`)
- Compression: STORE (без сжатия) — сохранено

### 9. Редактирование состава оборудования в начатом отчёте
- На странице чек-листа добавлена кнопка «Изменить состав оборудования»
- Модалка с +/- счётчиками для каждого типа оборудования
- При увеличении количества — добавляются новые секции
- При уменьшении — удаляются только пустые секции; если есть фото, показывается тост-запрет
- Существующие фото переносятся в обновлённые секции (по совпадению id)
- Отчёт сохраняется, чек-лист перерисовывается
