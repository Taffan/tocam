### 2. iOS — настройка сканера по умолчанию
**Статус:** ✅ Готово

### 3. Обновление — проверка интернета через fetch вместо navigator.onLine
**Статус:** ✅ Готово

- Реальная проверка: fetch `version.json` — если упал, тост «Обновление недоступно без интернета»

### 4. КЕ — 2 фото вместо 1
**Статус:** ✅ Готово
- data.js: KE-типы получают `multi: true, maxPhotos: 2`
- app.js: KE/SN handler открывает галерею при достижении лимита (вместо preview)
- app.js: кнопка «Сделать фото» в галерее КЕ открывает сканер
- app.js: `keCamCapture` проставляет `photoNumber`, `renderKECell` показывает счётчик `1/2`
- app.js: сканер поверх галереи — после закрытия галерея обновляется

### 5. Хранилище отчётов — защита от сброса кэша
**Статус:** ✅ Готово — два уровня:

**Уровень 1 — localStorage (всегда включён)**
- `saveReport()` дополнительно пишет stripped-копию (без фото) в localStorage
- `loadDrafts()` при пустом IndexedDB загружает из localStorage
- `deleteReport()` / `deleteCurrentReport()` чистят localStorage
- Ключи: `_rback_{id}` + `_rback_index`
- Переживает сброс кэша браузера

**Уровень 2 — File System Access (опционально, в Настройках)**
- Кнопка «Выбрать папку для сохранения» в настройках
- `window.showDirectoryPicker()` → `FileSystemDirectoryHandle` сохраняется в IndexedDB
- При каждом сохранении отчёта — пишет `.json` (без фото) в выбранную папку
- При загрузке приложения — читает `.json` из папки (восстановление после сброса)
- Поддерживается в Chrome/Edge/Opera (не iOS Safari)

### 6. Версия v1.0.5.8
**Статус:** ✅ Готово — `version.json: 1.0.5.8`, `sw.js: foto-reports-v20`
